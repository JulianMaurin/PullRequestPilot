Getting started

  1. Install the app from the Mac App Store and open it. The token setup appears on first launch.
  2. Create a GitHub token. The quickest option is a classic token with the repo scope. A fine-grained token works too; see which token to create.
  3. Paste it and click Save & Validate, then Get Started.
  4. Add your views. Create the four preset views in one click, or press ⌘N to write your own search.

Common questions

Which token should I create?

Either kind works:

  • Classic token: select the repo scope. Without it, pull requests from private repositories won't appear, and the app warns you about it.
  • Fine-grained token: give it read access to Pull requests, Checks and Commit statuses on the repositories you review, plus write access to Pull requests if you want to convert pull requests to drafts or mark them ready.
Pull requests from my organization are missing

If your organization uses SAML single sign-on, GitHub withholds its results until the token is authorized for it. On github.com/settings/tokens, open the token's Configure SSO menu and authorize the organization. The app tells you when results were withheld.

Organizations can also restrict fine-grained tokens; an owner may need to approve yours.

Where is my token stored?

In the macOS Keychain. It is only ever sent to GitHub's API. See the privacy policy for everything the app stores.

How often does the app refresh?

Every minute by default. You can choose anything from 30 seconds to 30 minutes in Settings, or press ⌘R to refresh now. Refreshing pauses while your Mac sleeps or is offline, and slows down when GitHub asks it to.

How do I add a widget?
  1. Right-click the desktop and choose Edit Widgets…, or open Notification Center and click Edit Widgets.
  2. Search for Pull Request Pilot and drag PR Overview or PR View into place.
  3. For PR View, right-click the widget, choose Edit “PR View” and pick the view to show.

Widgets show the data from the app's last refresh, so keep the app running (it lives in the menu bar). Settings can launch it at login.

I don't get notifications

Turn on the bell next to the view you want to follow. If the bell shows a warning, notifications are turned off for the app: open System Settings › Notifications › Pull Request Pilot and allow them.

Only pull requests that are new to a view are announced. Changing a view's search starts over, so existing results aren't announced as new.

“Open in VS Code, iTerm or cmux” doesn't appear

In Settings › Git Directories, add the folder that holds your clones. The app scans it in the background and offers the Open in items when a pull request's branch is checked out locally, in a worktree, or when its head commit is present. The item for an app appears only if that app is installed.

Pull requests from forks aren't matched by branch name, since a fork's branch name says nothing about your local clones.

Can I track issues too?

Yes. A view is any GitHub search, so is:issue assignee:@me works just like a pull request search.

How do I remove my data?

In Settings, click Sign Out. This deletes the token from the Keychain and clears the pull request data, including what the widgets show. The privacy policy explains how to remove everything else.
